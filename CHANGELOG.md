# Changelog

All notable changes to agent-kit are recorded here, newest first. The four plugins (`haiku-delegation`, `agent-guards`, `agent-eval`, `verification-runner`) and the marketplace entry are released together under one version number. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/) while below 1.0 (a new feature bumps the patch number).

**How to keep it.** Each pull request adds its own line under `## [Unreleased]` and does not change any version; a separate release step renames `[Unreleased]` to the version and date and bumps the versions. The full rules, the release steps and the pull request template are in [`CONTRIBUTING.md`](CONTRIBUTING.md). `tests/haiku-delegation/test_changelog.py` checks that this file and the version numbers agree.

## [Unreleased]

## [0.2.3] - 2026-10-15

### Changed
- **Behaviour change:** `/haiku-delegation:subagents-init` now refreshes by default. A `SUBAGENTS.md` that differs from the shipped one used to be reported (`EXISTS ... kept as it is`) and left alone until you ran `update`; now everything above "Project facts" is replaced with the shipped text, your own facts below it are kept, and `SUBAGENTS.md.bak-<timestamp>` is written first (`UPDATED SUBAGENTS.md (previous version: ...)`). The orchestrator rules block is refreshed the same way (only the text between the two markers, backup of the target file first). A `SUBAGENTS.md` with no "Project facts" section is still never touched: the default run keeps it and prints a note, `-Update` still refuses it. New flag `-Keep` (skill argument `keep`) gives the old behaviour (`EXISTS ... (-Keep)`, `ORCHESTRATION outdated`); `-Update` is still accepted and is now the default. If you had edited the shipped part above "Project facts", those edits are replaced (they are in the backup). Tests: `tests/haiku-delegation/test_subagents_init.py`.

### Fixed
- The main agent called `code-explorer` without its plugin prefix and got `Agent type 'code-explorer' not found`, because the kit told it the prefix was optional: the session policy (`plugins/haiku-delegation/policy/haiku-delegation.md`) said "the plugin prefix is optional", and `SUBAGENTS.md` (and its template copy) and the README said "the plain name also works". Plugin agents only resolve under their full name `<plugin>:<agent>`. All three texts now say so, and the session policy has a "Full names" line with every agent's prefix (`haiku-delegation:code-explorer`, `verification-runner:verification-runner`, `agent-guards:changelog-summarizer`, `agent-eval:annotator`, ...). Projects run `/haiku-delegation:subagents-init` to refresh their `SUBAGENTS.md`. `tests/haiku-delegation/test_agent_references.py` fails if a text says the prefix is optional or the policy lacks an agent's prefix.

## [0.2.2] - 2026-10-15

### Added
- New hook `guard-turn-budget` (`agent-guards`, PowerShell and shell, fails open) so a subagent that runs out of turns can still hand back a report. It counts each kit subagent's tool calls (per `agent_id`, in `turn-budget/` under the kit data folder) and, when the N-th call arrives, blocks that one call with a message: stop calling tools, write the final report now, start it with `PARTIAL` and list what was not done or not checked. N per agent is in `plugins/agent-guards/scripts/turn-budget.txt` (the old `maxTurns`). It never blocks again; the real cap is now 3 x N (`maxTurns` in each agent file, for example 90 for `code-explorer`), so the agent still has turns left to deliver the report, and the hand-back call itself is never counted. Each agent file got one operating-rules bullet that states the budget and the `PARTIAL` rule. Before this, an agent that hit its cap while still calling tools ended with no report (the usage log flags this as `no_final_answer`). Count files older than a day are removed when a new agent starts. Tests: `tests/agent-guards/test_guard_turn_budget.py`.

## [0.2.1] - 2026-10-15

### Added
- `/agent-eval:report-issue` lets a plugin user report errors to the maintainers as a GitHub issue. It reads `hook-errors.log` and `eval/annotations.jsonl` (last 30 days by default, `-Days N`), groups equal errors, and writes a draft to `reports/issue-draft-<time>.md` with counts, script names, the versions (kit, each of the four plugins, Claude Code, operating system) and sanitized messages (home folders and paths, tokens, long opaque strings and e-mail addresses replaced; never prompts, answers, transcripts or file contents). Nothing is sent until the user has read the draft and confirms: with `gh` logged in it checks for an existing issue with the same fingerprint and otherwise creates the issue; without `gh` it prints a prefilled browser link. The submit step sanitizes the draft again and accepts only files `issue-draft-*.md` inside `reports/`. The issue title starts with `[agent-kit <version>]` so reports sort by release. PowerShell and shell versions write the same draft (`tests/agent-eval/test_issue_report.py`, 95 checks).

### Changed
- `/haiku-delegation:subagents-init` now also adds the orchestrator rules to the project: a new shipped file `plugins/haiku-delegation/templates/AGENTS.md` (the "Orchestrator-First Execution" text) is written between a `<!-- agent-kit:orchestration:begin ... -->` and a `<!-- agent-kit:orchestration:end -->` line in the same `CLAUDE.md` or `AGENTS.md` that gets the `@SUBAGENTS.md` import. The file's own text stays byte for byte (a CRLF file gets a CRLF block), the same text already in the file without markers is not added twice (`ORCHESTRATION already present`), and a second run reports `ORCHESTRATION up to date`. `-Update` (skill argument `update`) replaces only the text between the markers after writing `<file>.bak-<timestamp>`; without it an outdated block is only reported. Damaged markers (a begin without an end, wrong order, two blocks) are refused with nothing written to the file. `-NoOrchestration` (skill argument `no-orchestration`) skips the block and `-Import none` skips the import and the block. Supported Claude Code is v2.1.277 or newer (from then on it reads an `AGENTS.md` by itself and expands `@` imports in it); this is noted in the README under "Platform" and in the skill. Tests: `tests/haiku-delegation/test_subagents_init.py`.

### Fixed
- `verification-runner` armed ten Monitor watchers on one log while retrying and could not stop any of them. Its instructions now say: a run that fits in 10 minutes goes in the foreground (tool timeout 600000) with no Monitor, a longer run gets exactly one Monitor and never a second, and when turns run low it reports `still running` with the log path instead of arming more.

## [0.2.0] - 2026-10-14

### Changed
- **Breaking:** nine agents are merged into two. `repo-scout`, `bulk-reader`, `module-mapper`, `inventory-extractor` and `test-case-lister` became `code-explorer` (kinds `locate`, `read`, `map`, `inventory`, `tests`); `schema-reader`, `contract-reader`, `migration-checker` and `api-contract-checker` became `contracts-reader` (kinds `schema`, `api-spec`, `migrations`, `api-match`). The agent count drops from 29 to 22. Start the brief with `Task kind: <kind>` (several kinds when a task mixes them); the agent applies that section's rules first. Callers that name an old agent (your own `CLAUDE.md`, prompts, settings deny rules, scripts) must switch to the new names; projects run `/haiku-delegation:subagents-init update` to refresh `SUBAGENTS.md`. Each section keeps the old agent's rules word for word; the shared operating rules are written once. `contracts-reader` runs at effort medium and `code-explorer` at low; the main agent can pass a different `effort` per call.
- **Breaking:** twelve more agents are merged into four topic agents, and the old names live on as kinds. `infra-reader` (kinds `pipeline-reader`, `dependency-reader`, `config-drift-checker`), `docs-reader` (`spec-extractor`, `doc-link-checker`, `doc-drafter`), `triage` (`log-triage`, `test-run-summarizer`, `ticket-classifier`) and `compliance-lister` (`audit-coverage-lister`, `secret-candidate-lister`, `citation-verifier`). The agent count drops from 22 to 14, and a seventh topic agent, `researcher` (kinds `doc-researcher`, `release-diff`, `advisory-collector`; default effort low, pass `medium`, `high` or `max` per call as the old agents ran), takes it to 12. The `researcher` kinds keep the "never says an upgrade or a version is safe" rules word for word; its web research could not be benchmarked offline, so it was checked live against the old agents instead. Call the topic agent with `Task kind: <old name>`; each section keeps the old agent's rules word for word (checked line by line). The merged agents default to effort low; `scripts/kinds.txt` lists the effort each kind ran at before, and the main agent passes `effort` per call for kinds that need more. Callers that name an old agent (your own `CLAUDE.md`, prompts, deny rules, scripts) must switch; run `/haiku-delegation:subagents-init update`. The `.env` guard (`agent-guards`) now covers `infra-reader` and `compliance-lister` as well as the old names, so the protection did not lapse with the merge.
- `SUBAGENTS.md` (and its template copy) now has a section "Two agents serve several kinds of task: say which kind" (kinds, default effort, the `effort` parameter, the guard hook), the first-line rule in "Writing a brief", the kind in annotator briefs, and a line about `guard-task-kind` under "Health and approvals". Projects run `/haiku-delegation:subagents-init update` to pick it up. The roster test now finds each table's `Agent` column from its header.
- Known trade-off of the merge: `maxTurns` of a merged agent is the highest of its old agents (`code-explorer` 30, `contracts-reader` 50), so the old tighter caps of `bulk-reader` (15) and `repo-scout` (20) are gone. Ask for narrow questions, or run `/agent-guards:kit-doctor` and the usage log to watch turns per run.
- New `guard-task-kind` hook (`haiku-delegation`, PowerShell and shell, fails open, `TASK_KIND_GUARD=off` disables): a brief for `code-explorer` or `contracts-reader` must start with `Task kind: <kind>`; otherwise the call is blocked once with the message that fixes it. The kind words from the brief are never glob-expanded and a bad word is echoed only in a short plain form. Matching is case-sensitive in both versions.
- The valid kinds of each topic agent now live in one table, `scripts/kinds.txt` (`<agent> <kind> <footers>`), read by `guard-task-kind` and, as a copy in `plugins/agent-eval/scripts`, by the usage log's footer checks. Adding a topic or a kind is a few rows plus a section in the agent file; `tests/haiku-delegation/test_kinds_table.py` fails when the copies, the rows and the agent sections disagree. Behaviour for the two existing agents is unchanged.
- `verification-runner` can now wait for a long run: it has the `Monitor` tool, and its guard accepts only one form of `Monitor` command, `until grep -q [-E] 'PATTERN' <log inside verification-logs>; do sleep N; done`, optionally followed by `tail -n K` of the same log. A WebSocket source, redirects, other commands and paths outside the log folder are blocked in both the PowerShell and the shell guard (`tests/verification-runner/test_guard_monitor.py`, 61 checks). Runs expected to exceed ten minutes start in the background and are watched with one `Monitor`.
- The bulk-read redirect (`agent-guards`) now tells the main agent to call `code-explorer` with `Task kind: read`, and the session policy and `SUBAGENTS.md` list the new names.
- The usage log (`agent-eval`) reads the brief's `Task kind:` line to choose the footer checks of the merged agents (for example `contracts-reader` with `schema` or `api-spec` must print Coverage and Reconciliation, with `migrations` or `api-match` it need not). Records written by older versions that carry the old agent types are still checked as before.

### Added
- `tests/haiku-delegation/test_agent_references.py`: fails when a hook, script, policy or doc names an agent that does not exist or a merged one that was removed; `tests/agent-eval/test_usage_log_task_kind.py` tests the kind-aware footer checks on both the PowerShell and the shell hook.
- `bench/merge-readers`: headless experiment comparing the five reader agents with one merged agent (with sections in the prompt, with sections as on-demand skills, and with a hook-written `Task kind:` marker). Results and limits are in its README. No shipped agent changed.

### Fixed
- The secret guard (`agent-guards`, `guard-secret-leak`) no longer replaces TypeScript generic types with `<redacted:secret>`. A line such as `const SECRET_LABELS: Record<string, string> = {}` lost `Record<string` because the key contains `SECRET` and the key/value rule took the type as the value; a generic type (`Record<`, `Map<`, `Promise<`) is now never a value, and plural key names (`labels`, `names`, `types` ...) are excluded like their singular forms. Real passwords and tokens are still redacted. Both the PowerShell and the shell guard; the shell guard now has its own test (`tests/agent-guards/test_guard_secret_leak_sh.py`).
- A subagent the user stopped could not be annotated: it never reaches the `SubagentStop` hook, so `usage/agent-usage.jsonl` had no record of it and the `annotator` found 0 matches. A new `SubagentStart` hook in `agent-eval` (`subagent-start-log`, PowerShell and shell) now writes a small start record (ids, agent type, time, transcript path; no prompt or answer) to `usage/agent-starts.jsonl`. The `annotator` falls back to it when there is no usage record, notes in the summary that the run was unfinished, and `annotate.py` records `run_record: start-only`. Nothing that reads `agent-usage.jsonl` changes. (`tests/agent-eval/test_stopped_run.py`)
- The bulk-read redirect (`check-bulk-read`) wrongly implied that a chunked read (`offset`/`limit`) is only for edits or exact line numbers. The message now says chunked reads are always allowed, for any purpose including reviews, and that only whole-file reads over the limit are redirected; the block texts of `check-bulk-read` and `guard-env-files` also say they are an intentional guard, not a hook failure. Claude Code itself prefixes every hook block with "hook error"; the kit cannot change that label. (`tests/agent-guards/test_guard_messages.py`)
- `tests/linux/pwsh` (the Linux test shim) is now pinned to LF in `.gitattributes`; a Windows clone with `core.autocrlf=true` checked it out with CRLF and the container suite failed with `FileNotFoundError: 'pwsh'`.

## [0.1.14] - 2026-10-14

### Added
- `/haiku-delegation:subagents-init`: copies `SUBAGENTS.md` into the current project root and adds an `@SUBAGENTS.md` import to `CLAUDE.md` (or `AGENTS.md`, or a new `CLAUDE.md`). Safe to repeat: an identical file is `UNCHANGED`, the import is never added twice, and a `SUBAGENTS.md` the project edited is kept. Options: `update` (refresh the shipped part above "Project facts", keep the project's facts, write `SUBAGENTS.md.bak-<timestamp>`; running it twice changes nothing), `dry-run`, `claude` or `agents` to choose the import target, or a folder path. Shell and PowerShell versions behave identically. User-started only.
- `SUBAGENTS.md`: new section "Report agent failures to the annotator: on your own initiative". The main agent records a verified failure of a subagent (false fact, wrong count, omission, broken rule, exposed secret, no usable answer) without the user having to ask: fix the task first, then call `annotator` once per failed run, and note it in the close-out line. Lists what not to annotate (style preferences, unchecked runs, its own vague briefs, duplicates).
- `CONTRIBUTING.md` and a pull request template: the changelog line goes in the PR, versions are bumped only in a separate release step (rules, release steps and notes for agents).
- README: "Set up each project (once per project)" explains how to put the roster into a project; "Update and uninstall" now says what to do in each project after a kit update; this changelog.
- Tests: `test_subagents_init.py` (both tools, identical output, idempotence), `test_changelog.py`.

### Changed
- `SUBAGENTS.md`: the "Standing handoffs" bullet for wrong or partial agent results now says to annotate without being asked; the close-out line adds `Annotated: <agent_type> <outcome>` or `Annotate: skipped, <reason>`.
- A copy of `SUBAGENTS.md` now ships inside `plugins/haiku-delegation/templates/` (an installed plugin cannot read the repository root). A test fails if the two copies differ.

## [0.1.13] - 2026-10-14

### Fixed
- Ubuntu and other Linux machines with a UTF-8 locale (`en_US.UTF-8`, `C.UTF-8`) never wrote a usage record: gawk 5 rejected the byte-range patterns of the checks program, the hook logged `run record not written: output checks failed` for every run, `usage/agent-usage.jsonl` was never created and the `annotator` rejected every run id as unknown. `subagent-usage-log.sh` now forces `LC_ALL=C` for its awk stages. Windows was not affected.
- The awk error text, which was thrown away, is now part of the `hook-errors.log` line, so a failure of this kind cannot hide again.

### Added
- `tests/agent-eval/test_usage_log_sh_locale.py` runs the real hook under the `C` locale and every installed UTF-8 locale and requires a run record. Fails on 0.1.12 under `C.utf8`.

## [0.1.12] - 2026-10-13

### Changed
- Linux runs native POSIX `sh` scripts: no PowerShell and no Python needed. `scripts/run.sh` is the OS-neutral launcher (`powershell.exe` on the PATH runs `<script>.ps1`, otherwise `<script>.sh`). Hooks, skills and the safe-rm rewrite no longer name a shell language in any command shown to a user or an agent.

### Added
- A `.sh` twin for every hook and tool (guards, secret redaction, browser guard, bulk-read redirect, usage log, annotator guard, `kit-policy`, `kit-doctor`, safe-rm, runner guard, session context), built on a shared `lib.sh`. Needs only `sh`, `awk`, `sed`, `grep` and coreutils; verified under `dash` and `mawk`.
- Tests for `lib.sh`, the launcher and shell purity; the Linux test image has no PowerShell. 16 suites pass on Windows and on Ubuntu 24.04.

## [0.1.11] - 2026-10-13

### Added
- Ubuntu Linux support alongside Windows (via PowerShell 7 at this version; replaced by native `sh` in 0.1.12). Safe-rm and the runner guard handle POSIX paths; `tests/linux` runs the suite in an Ubuntu 24.04 container.
- `SUBAGENTS.md`: roster of all 29 subagents and when the main agent should hand work to them, with standing handoffs, brief rules, a close-out line and a "Project facts" section. A test checks that every shipped agent is listed and no unknown agent is named.

## [0.1.10] - 2026-10-13

### Added
- Initial release: four plugins. `haiku-delegation` (read-only Haiku 5.5 subagents with effort tiers and a delegation policy), `agent-guards` (secret redaction, `.env` protection, bulk-read redirect, monitor guard, browser guard, read-only git), `agent-eval` (usage log with deterministic contract checks, `annotator` agent, judge and review CLIs), `verification-runner` (test, lint and build runner with safe-rm quarantine).
