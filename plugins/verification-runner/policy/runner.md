# Verification runner (verification-runner plugin)

- Running tests, linters, type checks or builds whose output is long or whose run is slow -> `verification-runner` (full output goes to a log file; you get the verdict, the first failures and the log path). Trusted repos only: it runs the project's own code. It can also `rm` files and folders inside the zones in safe-rm-policy.json (in the kit data folder): an `rm` is turned into a MOVE to a restorable quarantine (`safe-rm-restore.ps1 -List` / `-Id`), recorded with hashes in `_deletions.jsonl`; .git/.claude/.venv/.env*/keys/databases, project roots, symlinks and anything outside the zones are refused.
- Which commands the runner may run is decided by Claude Code's own permissions (your allow, ask and deny rules and the permission mode); the kit adds no list of its own. If the runner reports that a command was refused or needs permission, do not run it yourself around that: ask the user whether to allow it (they can approve the prompt or add a rule to their Claude Code settings), and re-run only after their answer.
