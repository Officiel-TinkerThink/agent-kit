Parcel status lookup: given a tracking number supplied by a caller, the system returns the current status of that parcel as one of LABELLED, IN_TRANSIT, OUT_FOR_DELIVERY, DELIVERED or EXCEPTION. The application use case trims and validates the tracking number, rejects an empty value, and delegates the lookup to a tracking port. An HTTP adapter implements that port by calling the tracking service at a base URL read from the TRACKING_BASE_URL setting, with a 5 second timeout. An unknown tracking number yields a not-found result, and a transport failure yields a clear error without exposing internal details. The composition root is the only place where the adapter is constructed and wired into the use case. Each lookup is logged with the tracking number and resulting status so that the access is traceable.
