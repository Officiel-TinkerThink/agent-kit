The user ran this to set up delegation in the current project. The tool never loses text: it creates `SUBAGENTS.md` (or refreshes it when it differs from the shipped one: only the part above "Project facts" is replaced, the project's own facts are kept, and a `.bak-<timestamp>` copy is written first), adds one `@SUBAGENTS.md` import line, and puts the orchestrator rules between a `<!-- agent-kit:orchestration:begin ... -->` and a `<!-- agent-kit:orchestration:end -->` line in the same file (an outdated block is refreshed the same way, only the text between the markers, backup first). Everything else already in that file stays byte for byte, and the rules are never added twice.

1. Map $ARGUMENTS to flags: `keep` -> `-Keep` (leave an existing `SUBAGENTS.md` and rules block as they are), `dry-run` -> `-DryRun`, `no-orchestration` -> `-NoOrchestration`, `claude` or `agents` -> `-Import claude|agents`, a folder path -> `-Project "<path>"`. No arguments means the git top level of the current folder, import and rules into `CLAUDE.md` if it exists, else `AGENTS.md`, else a new `CLAUDE.md`, refreshing whatever is outdated. Do not pass `-Update`; refreshing is already the default.
2. Run the tool directly; no dry run is needed first because every refresh writes a backup. Only use `dry-run` when the user asked for it.
3. Run exactly:
   `sh ${CLAUDE_PLUGIN_ROOT}/scripts/run.sh ${CLAUDE_PLUGIN_ROOT}/scripts/subagents-init [-Project "<path>"] [-Import claude|agents] [-Keep] [-DryRun] [-NoOrchestration]`
   A `REFUSED:` message is final: report it and do not work around it by editing the files yourself. Damaged markers (a begin line without an end line, the end before the begin, two blocks) are refused this way; the user fixes them by hand.
4. Report the lines it printed (`CREATED`, `UNCHANGED`, `EXISTS`, `UPDATED`, `MIGRATED`, `IMPORT added/already/created`, `ORCHESTRATION added/already present/up to date/outdated/updated/skipped`, `WOULD ...`, `ROOT`). `UPDATED SUBAGENTS.md (previous version: <backup>)` and `ORCHESTRATION updated ... (previous version: <backup>)` mean the shipped text was refreshed and the old file is in that backup; name the backup files. `MIGRATED SUBAGENTS.md (replaced by the shipped version; previous version: <backup>)` means the project's `SUBAGENTS.md` was an older one without a "Project facts" section: it is now the shipped file (one roster, not two) with a note under "Project facts" that names the backup; copy the project's own facts (paths, stale folders, exclusions, commands) from that backup into the list yourself or offer to, and name the backup file. `EXISTS` means the project's `SUBAGENTS.md` differs from the shipped one and was left alone because `keep` was given; `ORCHESTRATION outdated ... (-Keep)` means the block differs and was left alone because `keep` was given. `ORCHESTRATION already present ... (verbatim; no markers added)` means the same rules were already in the file without markers, so nothing was added.
   Supported Claude Code is v2.1.277 or newer: only from that version does Claude Code read an `AGENTS.md` itself (when there is no `CLAUDE.md`) and expand `@` imports in it. If the import went into `AGENTS.md`, mention this once, and that an older version needs a `CLAUDE.md` containing `@AGENTS.md`.
5. Tell the user the one thing left to do by hand: fill in the "Project facts" section at the bottom of `SUBAGENTS.md` (layout and stale folders, files agents must never read, the one command per verification gate). Offer to draft it with `code-explorer` (`Task kind: locate`), but write only what the user confirms. Nothing is committed.
